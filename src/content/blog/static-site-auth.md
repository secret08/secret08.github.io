每次讨论"静态博客怎么做登录"，都会有人给出这样的方案：

```js
if (localStorage.getItem('pwd') === '123456') {
  document.querySelector('.secret').style.display = 'block';
}
```

这不叫登录，这叫**装饰**。按 F12 打开控制台，一行代码就把内容调出来了；更狠一点直接右键查看网页源代码，明文就在 HTML 里躺着。

## 隐藏 URL 同样不行

常见的第二种做法是把敏感页面放在一个奇怪路径，比如 `/x8f2k-secret`，不告诉任何人。

问题是：

- 路径会出现在浏览器历史、Referer 头、CDN 访问日志里
- 搜索引擎可能爬到
- 一旦你分享给任何一个人，链接就脱离了控制

**靠别人不知道 URL 来保密，专业说法叫"隐晦式安全"，从来不被认为是真正的安全措施。**

## 静态站真正的两条路

### 路线一：内容加密，客户端解密

把敏感数据用 AES-256-GCM 加密成密文，密文文件可以公开放在 CDN 上——因为**没有密码，密文就是一堆随机字节**。

密钥通过 PBKDF2 从密码派生，迭代次数拉到几十万次量级，暴力破解的成本会变得很高。

优点：

- 读取路径是纯静态文件，CDN 边缘直出，速度最快
- 不需要任何后端服务，不需要数据库
- 密文可以放心放在公开仓库

缺点：密码强度决定一切。密码是 `123456`，再好的算法也救不了。

### 路线二：边缘函数鉴权

请求先到边缘节点，函数校验身份后才放行内容。Cloudflare Access、自建 Worker 都是这个思路。

优点是体验好（一次登录长期有效，可以做多人协作）；代价是需要一个能执行代码的地方，并且通常要求域名走平台的代理网络。

## 我怎么选的

**两者都用了**：

- 收藏链接 → 加密方案，读得快，省一次网络往返
- 需要在线编辑的场景 → 边缘函数写入

判断标准很简单：**只读的东西就该加密，需要改的东西才需要服务端。**
